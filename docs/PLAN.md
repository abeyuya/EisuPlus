# 実装計画: Kanary風キーボード/ウィンドウ操作アプリ（個人用）

macOS 27 で BetterTouchTool が使えなくなったため、以下の機能を持つ個人用 macOS アプリを自作する。
参考: [Kanary キーボード機能](https://kanary.to/ja/keyboard)

## 要件

- 左⌘で英数、右⌘でかなに入力を切り替える（Kanary と同じ挙動）
- 修飾キー + マウス移動で、マウスオーバー中のウィンドウを移動する（キーバインドは設定可能。デフォルト: `ctrl` + マウス移動、クリック不要）
- 修飾キー + マウス移動で、マウスオーバー中のウィンドウをリサイズする（キーバインドは設定可能。デフォルト: `option` + マウス移動。右下の角を動かす）
- ウィンドウ移動中にカーソルが画面の左端・右端に来たら、画面の左半分・右半分にリサイズする。上端に来たら最大化する

## 前提と技術方針

| 項目 | 方針 |
|---|---|
| 言語/UI | Swift 6.2 + SwiftUI（設定画面）+ AppKit（オーバーレイ等）。Xcode 26.3 |
| アプリ形態 | メニューバー常駐アプリ（`LSUIElement=YES`、`MenuBarExtra`）。対象は macOS 15 以降（設定ウィンドウの `defaultLaunchBehavior` のため） |
| サンドボックス | **無効**。他アプリのウィンドウを Accessibility API で操作するため、サンドボックス内ではできない |
| 配布 | 自分用なので Notarization は不要 |
| 署名 | **個人の Developer ID Application 証明書（Team `37XL3EDJ44`）で手動署名する**。ad-hoc 署名だとビルドのたびにアクセシビリティ権限がリセットされる。手元の Apple Development 証明書は会社のチームのものなので使わない |
| プロジェクト管理 | XcodeGen（`project.yml`）を使う。CLI の `xcodebuild` でビルド・確認する |
| 必要な権限 | アクセシビリティ（イベントの書き換え・握りつぶしと、他アプリのウィンドウ操作に必要） |

### 参考になる OSS

- [Easy Move+Resize](https://github.com/dmarcotte/easy-move-resize): 修飾キー＋マウスでの移動・リサイズがほぼそのまま入っている
- [Rectangle](https://github.com/rxhanson/Rectangle): スナップ、マルチディスプレイの計算、AX 操作の癖への対処
- ⌘英かな: 左右 ⌘ 単押しの判定

## アーキテクチャ

```
App (MenuBarExtra / Settings Window)
 ├─ PermissionManager      … AXIsProcessTrusted の確認と誘導
 ├─ EventTapManager        … CGEventTap は1つだけ。専用スレッドで動かし各ハンドラへ振り分ける
 │    ├─ InputSourceSwitcher   … 左右⌘の単押し → 英数/かな
 │    └─ WindowGestureController … 移動/リサイズの状態機械
 ├─ WindowLocator          … カーソル下のウィンドウを AXUIElement で取得
 ├─ WindowOperator         … AX で位置・サイズを設定（専用キュー＋間引き）
 ├─ SnapController         … 画面端の判定と半分フレームの計算
 │    └─ SnapPreviewWindow … 半透明のプレビュー（BTT風）
 └─ SettingsStore          … Codable を UserDefaults に保存
```

### イベントタップの設計

- 監視するイベントは `flagsChanged`、`keyDown`、`mouseMoved`、`left/rightMouseDown/Up/Dragged`、`scrollWheel`
- コールバックの中では判定だけを行い、AX 呼び出しは別キューに回す。AX は重く、コールバックが遅れるとタップが `kCGEventTapDisabledByTimeout` で止まってしまう
- `kCGEventTapDisabledByTimeout` と `kCGEventTapDisabledByUserInput` を受け取ったら再度有効にする

## 機能ごとの実装方針

### 1. 左⌘ → 英数 / 右⌘ → かな

- `flagsChanged` の keyCode（左⌘=55、右⌘=54）で押下と解放を検知する
- **「単押し」の判定**: 押してから離すまでの間に他のキー入力やマウスクリックがあればキャンセルする。長押しの閾値（例: 500ms）も設ける
- 切り替えは `kVK_JIS_Eisu(102)` / `kVK_JIS_Kana(104)` のキーイベントを送る方式を採用する（⌘英かなと同じで、US 配列でも動く）
  - 代替案の `TISSelectInputSource` は、日本語 IME で表示が追従しない既知の問題があるので予備にとどめる

### 2. ウィンドウ移動（キーバインドは設定可能）

- **バインド設定モデル**

  ```swift
  struct GestureBinding: Codable {
      var modifiers: Set<Modifier>   // control, option, command, shift, fn
      var trigger: Trigger           // .mouseMove（ボタン不要）/ .leftDrag / .rightDrag
  }
  ```

  修飾キーは**完全一致**で判定する。移動が `ctrl`、リサイズが `opt` のとき、`ctrl+opt` はどちらにも該当しない。
- **状態機械**: `idle → armed`（修飾キーが一致）`→ active`（最初の移動でウィンドウを捕まえる）`→ idle`（修飾キーを離す、またはマウスアップ）
- **ウィンドウの特定**: `AXUIElementCopyElementAtPosition(systemWide, x, y)` から `kAXWindowAttribute` をたどる。ウィンドウは開始時に1回だけ捕まえ、移動中は捕まえ直さない
- **移動**: 開始時の位置からの差分を `kAXPositionAttribute` に設定する。約60fpsに間引き、古いリクエストは捨てて最新だけを反映する
- **⚠️ ctrl + クリックは macOS では右クリック扱い**になる。トリガーをドラッグにした場合は mouseDown/Up/Dragged を握りつぶし（タップで nil を返す）、コンテキストメニューやテキスト選択が起きないようにする（フェーズ0で動作確認済み）

### 3. ウィンドウのリサイズ（キーバインドは設定可能）

- 移動と同じ状態機械を使い、モードだけ `.resize` にする
- **どこを基準に伸縮するか**: 常に左上を固定し、右下の角を動かす（象限方式は試したうえで不採用）
- 最小サイズ（120×80）より小さくはしない
- Chrome など一部のアプリでは `AXEnhancedUserInterface` を一時的に false にする。こうしないとアニメーションが入って重くなる（Rectangle と同じ対策）

### 4. 移動中の画面端スナップ

- 移動中、カーソルがあるスクリーンの `visibleFrame` の左端・右端から閾値（例: 5px）以内に入ったら、左半分・右半分のプレビューを出す
- **確定するタイミング**: マウス移動方式（デフォルト）なら修飾キーを離したとき、ドラッグ方式ならマウスアップ時（プレビューで取り消しの余地を残すため）
- **スナップ前のサイズを覚えておく**: スナップ済みのウィンドウを再び動かしたら元のサイズに戻す（BTT の挙動）
- **マルチディスプレイ**: 隣のディスプレイと接している辺は「端」とみなさない（カーソルがそのまま抜けてしまうため）
- **座標系の変換**: AX と CGEvent は左上原点、NSScreen は左下原点なので、変換用のユーティリティを1か所にまとめる
- 上端に来たら最大化（`visibleFrame` いっぱい）する。角では左右半分を優先する。設定で ON/OFF 可能

## 日常使いへのインストール

```bash
./scripts/install.sh
```

Release ビルドを `/Applications/Btry.app` に配置して起動し直す。署名が同じなのでアクセシビリティ権限は引き継がれる。
ログイン時の起動は、設定画面の「ログイン時に起動」から `/Applications` 版で有効にする。

## 既知の落とし穴

- 権限を付与した直後はタップの作成に失敗することがあるので、ポーリングして作り直す
- フルスクリーンのウィンドウとデスクトップ（Finder の AXScrollArea）は対象外にする
- **自アプリへの AX 問い合わせは呼び出し元スレッドで処理される**ため、ウィンドウ操作キューから自アプリの要素を問い合わせると SwiftUI がメインスレッド外で動いてクラッシュする。AX を呼ぶ前に CGWindowList で所有者を確認し、自アプリのウィンドウは NSWindow をメインスレッドで直接操作する
- AX 操作への反応が遅いアプリ（Electron 系）は、間引きで吸収する
- 修飾キーを押したまま別のアプリに切り替わった場合などに状態が取り残されないよう、`flagsChanged` を毎回見直してリセットする

## 決定事項（デフォルト）

以下はデフォルトとして採用し、必要に応じて設定で変更できるようにする。

1. **スナップの確定タイミング**: 手を離したときに確定する（プレビューあり）
2. **リサイズの基準**: 常に右下の角を動かす
3. **移動のトリガー**: デフォルトは「ctrl + マウス移動」（クリック不要）。ドラッグ方式も設定で選べるようにする
